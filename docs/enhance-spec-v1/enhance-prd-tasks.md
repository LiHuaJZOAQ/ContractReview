## 二、需求现状分析（基于 `ai/auto/redesign` 分支）

> 说明：以下逐条核对需求在 `ai/auto/redesign` 分支的实现情况，标注状态
> ✅ 已完成 ｜ 🟡 部分完成 ｜ ⬜ 未完成，并给出佐证（提交号 / 代码位置）。

### 需求 1：LLM API 返回 404 排查 + 完善 log 系统（原标 [ ]）

**状态：✅ 已完成**

- **404 根因已修复**：`SpringAiConfig` 中自定义的 `RestClient.Builder` Bean 覆盖了 Spring AI OpenAI 自动配置的 HTTP 客户端，导致请求缺少 `base-url` 与 `Authorization` Header。已移除该 Bean（提交 `2ce075a`）。
- **日志系统已完善**：
  - 新增 `MdcFilter` + `AccessLogFilter`，实现 MDC 全链路标识（`traceId`/`userId`）与请求级访问日志（提交 `d064266`）。
  - 新增异常分级处理与结构化日志（`logback-spring.xml`，dev 控制台可读 / prod JSON 结构化，提交 `a3f5078`、`b03f2c1`）。
  - 新增 Actuator 健康检查与全部基础设施服务 Docker 健康检查（提交 `673ce9d`）。
  - 新增 LLM 启动连通性测试 `ApplicationRunner`，启动即探测 LLM 端点并输出明确告警日志（提交 `5748bc9`）。

### 需求 2：合同文本支持 word、txt 和文本框粘贴输入（原标 [x]）

**状态：✅ 已完成**

- `FileUtil` 支持 `.pdf` / `.docx` / `.txt` 三种格式解析（Apache PDFBox + Apache POI）。
- 新增粘贴文本接口 `POST /api/v1/contract/paste` 与 `PasteRequest`。
- 前端 `Upload.vue` 提供"文件上传 / 文本粘贴"双模式（提交 `b1f5034`）。

### 需求 3：完善重试机制，审查页面出现异常可以重试（原标 [ ]）

**状态：🟡 部分完成**

- **后端已具备**：RabbitMQ DLX 死信队列自动重试（最多 3 次）+ 手动重试接口 `POST /api/v1/contract/{taskId}/retry`（`ReviewMessageListenerImpl`、`ContractServiceImpl.retry`）。
- **前端部分具备**：历史页（History.vue）对 `FAILED` 任务提供"重试"按钮。
- **缺口**：审查进行页（Upload 页内嵌的 `SseProgress`）在 SSE 推送 error 时仅弹出错误提示（`onError`），**没有重试操作按钮**，无法在审查页面原地重试。

### 需求 4：审查历史页查看进度需看到原合同文本与当前进度（原标 [ ]）

**状态：✅ 已完成**

- 历史页（History.vue）对进行中任务提供"查看进度"按钮，打开进度面板：
  - 展示合同预览文本（调用 `/contract/{taskId}/text`，提交 `660d219`）。
  - 内嵌 `SseProgress` 组件实时展示阶段进度与当前输出。

### 需求 5：剩余额度并没有扣减（原标 [ ]）

**状态：🟡 基本完成，存在展示不同步风险**

- **扣减逻辑已修复**：`submit` 时通过 Lua 脚本 `quota_deduct.lua` 在 Redis 原子扣减；当 Redis key 缺失时以 DB 中额度值为基准初始化后再扣减（提交 `8ea7406`、`59a3e40`）。
- **失败回滚**：审查失败后 Redis 与 DB 额度各 +1 回滚（`ReviewResultHandlerImpl` / `ReviewMessageListenerImpl`）。
- **遗留风险**：扣减仅写入 Redis，DB 表 `user.review_quota` 未随提交同步扣减，而个人中心 `getProfile` 从 DB 读取额度，**展示值可能不等于真实剩余额度**。该问题并入任务清单 T2 一并解决。

### 需求 6：没有个人中心（原标 [x]）

**状态：✅ 已完成**

- 后端：`UserController` + `UserServiceImpl`，提供个人信息、修改密码、自定义 API 配置（提交 `7a3390f`）。
- 前端：`Profile.vue` 页面 + 路由 `/profile` + 顶栏入口（提交 `931fffd`）。
- 权限：新增 `role` 字段与 ADMIN/USER 角色，前端按角色控制导航项。

### 需求 7：加一个管理后台，参考 RuoYi 框架（原标 [ ]）

**状态：🟡 部分完成**

  - **系统日志监控**（看后端 / 前端 / docker 容器日志）。

### 需求 8：embedding 模型寻找替代方法（原标 [ ]）

**状态：⬜ 未完成**

## 四、执行建议

1. **优先级**：先完成 P0（T1-T6），快速收口现存缺陷与展示问题，再进入功能迭代。
2. **依赖关系**：T11 依赖 T10（embedding 替代）与 T7（法规库上传）；T13 依赖 T12 与既有报告模块；T9 依赖日志体系（已在 ai 分支具备基础）。
3. **回归验证**：每个任务完成后运行 `mvn test` 与 `cd web && npm test`，确保既有 100+ 后端用例与前端用例不回归。
